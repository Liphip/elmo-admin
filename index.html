Data Storage & Transmission
  • No data is transmitted to the developer. All API requests go directly from your browser to the Element IoT API.
  • API credentials are stored only in your browser's localStorage (if you enable "Remember credentials").
  • No analytics, tracking, or cookies are used.
  • The Network map makes no external requests by default. A base map (OpenStreetMap tiles) is only loaded after you enable it on the map or in Configuration; then only tile coordinates are requested — no device data is sent.
  • Device data is loaded into memory only and is cleared when you close the browser tab.
How It Works

Elmo is a client-side web application that connects directly to the Element IoT API. It allows you to:

Devices
  • View, search, and filter all devices
  • Edit device names
  • Add/remove devices from folders
  • Send actions to devices
  • Bulk operations on multiple devices
Folders & Mandates
  • Create and manage folders (tags)
  • View mandates and their devices
  • Organize devices into folders
Actions
  • View recent action history
  • Create and schedule new actions
  • Cancel pending actions
Network
  • Map of gateways and devices
  • Which gateway receives which device (RSSI, SNR, link margin)
  • Find silent, weak and single-gateway devices
  • Estimate areas without reception — also where no devices exist yet
  • Export links and coverage cells as CSV
API Log
  • Monitor all API requests
  • Debug connectivity issues
  • Export logs for support

  1. Go to the Configuration tab in the sidebar
  2. Enter your Element IoT domain (e.g., https://your-instance.element-iot.com)

Devices
Gateways (devices with a gateway-management interface)
Data
Scopes are applied as API filters where possible (mandate, folder, name, gateway interface) to keep the number of requests low. In Gateway links mode uplinks are streamed per folder (one request per folder, window chosen from ELEMENT's packet intervals); only devices that deliver too few packets that way are loaded individually. Devices whose last uplink (ELEMENT statistics) is older than the time window are rated silent without a request. Quick mode uses only ELEMENT's device statistics: no packet requests, but no per-gateway links and no reception estimate.

Choose a scope and click Analyse.

Gateways
Selection

Click a gateway or device on the map (or in the tables below) to see which gateways receive which devices.

How devices are rated
  • Good — heard by ≥ 2 gateways with a healthy best link.
  • Single gateway — only one gateway hears it: no redundancy.
  • Weak — best link below the RSSI or link-margin threshold.
  • Silent — no uplink in the time window.
  • No gateway data — packets carry no gateway stats (e.g. created manually or via API).

Link margin = SNR − demodulation floor of the spreading factor (SF7 −7.5 dB … SF12 −20 dB).

Reception map: a log-distance path-loss model (RSSI = RSSI1 km − 10·n·log10(d)) is fitted to the measured links, per gateway where enough data exists. Each cell gets the best predicted RSSI of all receiving gateways: none below the weak RSSI threshold, marginal within the fade margin, single/covered for one/two or more gateways above it. Where devices exist, their measured rating overrides the prediction. Terrain and buildings are only reflected through the fit — treat areas without devices as an estimate.
